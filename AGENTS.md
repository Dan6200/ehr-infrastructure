## Git workflow

- Commit every change you make, grouped into focused, logically related commits. Do not include unrelated pre-existing work or another contributor's changes.
- Push important completed changes to `origin/main` so cloud agents that work through GitHub can access them. Treat completed feature and bug fixes, security changes, and project-wide instruction changes as important. Never force-push.

## Source of truth for work

- Use GitHub issues as the source of truth for feature, bug, and todo lists. Check the current issue before starting issue work; do not rely on stale handoffs, notes, or local task lists for issue status or acceptance criteria.
- When an issue is completed and its acceptance criteria are met, update/close the GitHub issue with the result. Keep issues open when work or required verification remains.
